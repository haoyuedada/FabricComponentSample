Breaking Change 详细分析 — startNotificationUseBuffer → startNotificationWithBuffer：

- PR #1377 将 JS 层 `startNotificationUseBuffer` 重命名为 `startNotificationWithBuffer`
- 这是对上游原有命名不一致的修正：Android 原生层方法名是 `startNotificationWithBuffer`，但 JS 层错误地写成了 `startNotificationUseBuffer`
- TurboModule Spec 文件中同步改名：`NativeGeneratedBleManagerTurboModule.ts` 中接口名变更
- 鸿蒙侧影响：
  - `src/index.ts`：方法名需从 `startNotificationUseBuffer` 改为 `startNotificationWithBuffer`
  - `src/NativeGeneratedBleManagerTurboModule.ts`：Spec 接口名需同步修改
  - `harmony/ble_manager/src/main/ets/generated/turboModules/ReactNativeBleManager.ts`：生成的 TurboModule 类型定义需同步
  - `harmony/ble_manager/src/main/cpp/generated/ReactNativeBleManager.cpp`：C++ 桥接层方法名需同步
  - `harmony/ble_manager/src/main/ets/BleTurboModule.ts`：鸿蒙原生实现方法名需同步

##### 架构变化

1. RN 框架升级（0.77 → 0.82）及支持 autolink 带来的变化：

| 变化项 | 0.77 架构 | 0.82 架构 | 影响 |
|-------|----------|----------|------|
| Package 基类 | `RNPackage` | `RNOHPackage` | BlePackage 需修改继承基类 |
| 入口文件 | `ts.ts` | `ts.ets` | 类型声明入口文件扩展名变更 |
| 模块导出方式 | `index.ets` 仅 re-export | `index.ets` 需 default export BlePackage | autolink 注册要求 |
| Autolink 配置 | 无 autolinking 配置 | 需配置 etsPackageClassName / cppPackageClassName / cmakeLibraryTargetName / ohPackageName | 0.82 框架新增 autolink 机制 |
| BlePackage 文件扩展名 | `BlePackage.ts` | `BlePackage.ets` | 0.82 框架要求 .ets 扩展名 |

2. startNotificationWithBuffer 功能实现新增的架构变化：

| 变化项 | 说明 |
|-------|------|
| 新增 NotifyBufferContainer 类 | 通知数据缓冲容器，管理 BLE 通知数据的缓冲和批量发送 |
| BleTurboModule 新增成员变量 | `bufferedCharacteristics: Map<string, NotifyBufferContainer>` 和 `unifiedListenerDevices: Set<string>` |
| BLECharacteristicChange 监听重构 | 从 `onBleCharacteristicChange` 直接发送模式，改为 `ensureUnifiedListener` 统一监听 + 缓冲区分发模式 |
| stopNotification 实现 | 原为 throw Error，现需实现：关闭通知 + 清理缓冲区 |
| disconnect 清理逻辑增强 | 断开连接时需清理缓冲区、注销系统监听器、清理 unifiedListenerDevices |
| clearPeripheral / disconnectPeripherals 增强 | 需同步清理缓冲区和监听器状态 |
| readDescriptor / writeDescriptor 防御性增强 | 增加 descriptorValues 未找到时的 reject 处理 |

BleTurboModule.ts 详细变更规格：

1. 新增 import：`import NotifyBufferContainer from './NotifyBufferContainer'`
2. 新增成员变量：
   - `private bufferedCharacteristics: Map<string, NotifyBufferContainer> = new Map()`
   - `private unifiedListenerDevices: Set<string> = new Set()`
3. `startNotificationUseBuffer` → `startNotificationWithBuffer`，从 `throw Error` 改为完整实现：
   - 检索外设和服务
   - 开启底层通知 `setCharacteristicChangeNotification(characteristic, true)`
   - 创建专属缓冲区 `NotifyBufferContainer`
   - 确保统一监听器已注册 `ensureUnifiedListener`
4. `stopNotification` 从 `throw Error` 改为完整实现：
   - 清理缓冲区 `bufferedCharacteristics.delete`
   - 关闭底层通知 `setCharacteristicChangeNotification(characteristic, false)`
5. `startNotification` 方法增强：
   - 增加 characteristics/descriptors 空值校验
   - 改用 `ensureUnifiedListener` 替代 `onBleCharacteristicChange`
6. `readDescriptor` 增强：增加 descriptorValues 未找到时的 reject
7. `writeDescriptor` 增强：增加 item 为 null 时的 reject
8. `disconnect` 增强：清理缓冲区、注销系统监听器、清理 unifiedListenerDevices
9. `clearPeripheral` 增强：注销所有系统监听器、清空缓冲区和监听器集合
10. `disconnectPeripherals` 增强：注销监听器、清空缓冲区和监听器集合
11. `onBleCharacteristicChange` 重构为 `ensureUnifiedListener`：
    - 幂等性：已注册则跳过
    - 缓冲区分发：有缓冲区则缓冲后 emit，无缓冲区则直接 emit
    - 注册成功后加入 `unifiedListenerDevices`

NotifyBufferContainer 类规格：

```typescript
class NotifyBufferContainer {
  private buffer: Uint8Array
  private writePos: number = 0
  public readonly capacity: number

  constructor(size: number)  // size 必须 > 0
  get items(): Uint8Array    // 已写入数据的只读视图
  get isBufferFull(): boolean // 缓冲区是否已满
  resetBuffer(): void        // 清空缓冲区（重置写指针）
  put(value: Uint8Array): Uint8Array // 写入数据，返回剩余数据
}
```

### 交付验收

#### 1. 代码审查

审查要点清单：

| 审查维度 | 审查项 | 风险等级 | 说明 |
|---------|-------|---------|------|
| 接口兼容性 | startNotificationUseBuffer → startNotificationWithBuffer 重命名是否在所有层级同步 | 高 | JS层、Spec层、C++层、ETS层、类型定义层共5处需同步 |
| 接口兼容性 | 旧方法名调用方是否全部更新 | 高 | 需确认无遗漏的 startNotificationUseBuffer 调用 |
| 内存管理 | bufferedCharacteristics 和 unifiedListenerDevices 是否在所有退出路径清理 | 高 | disconnect/clearPeripheral/disconnectPeripherals 均需清理 |

| 线程安全 | ensureUnifiedListener 的并发调用安全性 | 中 | 多次快速调用是否会导致监听器重复注册 |
| 类型安全 | NotifyBufferContainer 构造参数校验 | 低 | capacity <= 0 已有 throw 保护 |
| 崩溃风险 | startNotificationWithBuffer 中 characteristics/descriptors 空值访问 | 高 | 已增加空值校验 |
| 崩溃风险 | readDescriptor/writeDescriptor 未找到时继续访问 | 中 | 已增加 null 检查 |
| 架构适配 | BlePackage 基类 RNOHPackage 替换是否完整 | 高 | 需确认 RNOHPackage API 兼容 |
| 架构适配 | autolink 配置项是否正确 | 中 | etsPackageClassName/cppPackageClassName 等需与实际类名一致 |
